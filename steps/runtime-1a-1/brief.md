## The decisions, as their author wrote them

**1.** Ship three provisional reserve pairs in 1a. **2.** Let the installer name the environment in the root marker. **3.** Keep a POSIX shell entry with a pinned, dependency-free Node admission helper before npm. **4.** Keep two independently deliverable commits, with enforcement and all caller migrations together in the second. **5.** Require a regression scenario for each existing barrier below. **6.** Amend the specification to cover the current command surface, require token masking before persistence, and keep full gate confinement as a separate roadmap item.

### 1. Free-space floors

These are my **initial operating-policy choices**, in bytes. The repository establishes the need for two independent comparisons, the workstation failure, and the later measurement protocol. It supplies no measured safe threshold for any environment. A floor is the point at which I would refuse to **start** work. Passing it cannot guarantee that the run will finish with space left. `docs/design/orchestration-fable-5-2.md:918`, `:938`, `:944`, `:979`, `:985`.

| Marker environment | Runtime root floor, bytes | Actual user home floor, bytes | Reason for the initial choice |
|---|---:|---:|---|
| `workstation` | `34359738368` (32 GiB) | `17179869184` (16 GiB) | The development volume has room to enforce a substantial reserve before another build or gate starts. The separate home reserve addresses the disk that filled on 18 November and leaves the owner room to keep using the machine. Both floors pass today. |
| `hosted-runner` | `4294967296` (4 GiB) | `2147483648` (2 GiB) | An ephemeral runner serves one job and need not protect an interactive workstation. | `server` | `68719476736` (64 GiB) | `17179869184` (16 GiB) | My provisioning assumption is a persistent, multi-session host. There is no server observation or measured concurrency factor behind it. |


Put the three rows in `tools/runtime/admission.json`, with canonical positive decimal byte strings, a policy version, and explicit provenance per row: `status: "provisional"`, the basis above, and a review trigger naming step 4. Require exactly those three names and both fields per name. Expose the selected name, policy version, status, floors and starting observations in the receipt. Compare unprivileged available bytes using integer arithmetic and strict `>` for **each** floor, including on a shared device. Test one byte below, equality and one byte above for each comparison, an unreadable sample, and both paths on one device. Refuse before allocating a run. Step 4 then measures a step, a gate, and overlapping runs by repeated sampling. Waiting for that study would reverse the agreed construction order. `CLAUDE.md:69`, `:84`; `step-1a-spec.md:80`, `:88–91`, `:109`; `docs/design/orchestration-fable-5-2.md:985`.

### 2. The environment comes from the installer marker

Keep `ARCHITECT_OS_RUNTIME_ROOT` as the sole caller setting. I choose a strict, versioned marker, for example the exact two lines `architect-os-runtime-root/v2` and `environment=hosted-runner`, each LF-terminated. The workstation and server installers write their respective names. The entry opens and validates the marker under the canonical root, then uses its name to select policy from the **launcher checkout**. Floors never come from the marker. Missing, old, malformed, duplicate or unknown names refuse before writes or dispatch. There is no default, OS inference, CI flag, or second caller setting that can select a cheaper floor for the same installation.

This binds a provisioning decision to the place being admitted and preserves the existing fail-closed response to an absent volume or unmarked mount stub. On CI each job creates its own short physical root under `RUNNER_TEMP` immediately after checkout and before setup or installation, writes the hosted marker, and publishes only the root path. Each entry performs admission again. This is a runtime policy name, **never** a GitHub job `environment`, which would change the broker's OIDC subject. The public marker protects against accidental substitution; it does not authenticate a volume against someone able to replace both directory and marker. `step-1a-spec.md:72–76`, `:113–128`; `docs/design/orchestration-fable-5-2.md:963–964`, `:971`, `:979`; `features/steps/workflows.ts:125–135`.

### 3. Node is a host prerequisite

Keep `./aos -- PROGRAM [ARG ...]`. Shell handles grammar, the missing root setting and final `exec`. Admission uses the trusted host Node pinned by `.nvmrc` to **26.11.1**, built-ins only, from the trusted checkout. This lets the same implementation inspect the opened marker, do integer filesystem arithmetic, allocate the run exclusively and exercise the policy under mutation. A second implementation in shell would give reviewers two admission paths to reconcile. Missing or unsupported Node must produce a named refusal before npm, tsx, report removal or any repository write. Bootstrap with a clean environment and trusted executable path, excluding inherited preload, coverage and compile-cache writes. `package.json:8`; `.nvmrc:1`; `step-1a-spec.md:13–17`, `:82–90`; `tools/test-gate/gate.json:3–12`.

Apply the same distinction to a direct tsx loader. On CI the shell provisioning step can run before Node setup, and automatic package-manager caching must be disabled wherever setup could otherwise invoke npm early. `step-1a-spec.md:35–41`, `:113–128`, `:149`; `tools/test-gate/gate.sh:19–23`.

## The specification, as its author wrote it (the decisions above supersede it where they differ)

I would implement **one public launcher, `./aos`, with admission before npm**, and make every repository command fail closed when invoked outside an admitted run. There are two decisions to put explicitly in the brief. First, a repository can refuse a bare `npm run gate`, but cannot prevent that independently started npm process from writing its own startup log. Second, the design specifies two free-space floors but gives neither a value. Both affect what the maintainer can accept as proven. Design, lines 935–944 and 959–975

All names, paths, exit conventions and file formats below are **proposed** unless identified as existing.

## 1. Public entry and command contract

Place an executable `aos` at the repository root, with `#!/bin/sh`. Its public grammar is:

```text
aos -- PROGRAM [ARG ...]
```

`--` is required. The launcher preserves the caller's working directory, stdin, stdout, stderr, argument boundaries and terminal. It finds its own checkout from its executable path, independently of the caller's directory. It executes the admitted command with `exec "$@"`. It does not evaluate a command string, source an environment file, or ask git or npm to locate the repository. The one user setting is `ARCHITECT_OS_RUNTIME_ROOT`, an absolute physical directory explicitly selected by the installer. There is no default, discovery by walking up directories, or creation of an absent root. This preserves the existing distinction between the trusted launcher checkout and the target worktree. Code and step take their target from `INIT_CWD`, which `npm --prefix` supplies. Design, lines 935–938 · code-tool.ts, lines 115–140 · step-tool.ts, line 642

**Bootstrap order.** Validate the grammar and reject a missing setting in sh. Invoke the checkout's admission helper with **plain Node and built-ins only**, from source, before loading npm, tsx, workspace modules or compiled output. Run that helper with a clean bootstrap environment: an explicit trusted executable search path, no inherited `NODE_OPTIONS`, loaders, coverage output or compile-cache location, and compile caching disabled. Its success output is exactly one host-generated run basename. The shell validates that basename, derives the paths below itself, exports them, and execs the command. Diagnostics go only to stderr. “No dependency” here means no installed **project** dependency; Node is the project's existing host prerequisite. If the maintainer means a machine with only POSIX utilities and **no Node**, that is a different bootstrap contract and should be stated before implementation. `.nvmrc`, line 1 · package.json, lines 8–10 · local Node declarations for disabling the compile cache, lines 54–59

Let `R` be the validated root and `D=R/run/<id>`. Allocate `<id>` atomically using Node `mkdtemp` beneath the verified `R/run`, with prefix `r`; take the basename of the directory actually created. Do not accept caller-supplied IDs, use timestamps or PIDs as unique names, or reuse a previous run. Use a private umask. Short names matter: the existing runner adds `aos-sb/s-XXXXXX/tmp`, budgets another 24 characters for the socket and refuses a path longer than 103 characters. Include a real hosted macOS launch in acceptance. srt-runner.ts, lines 378–383 and 412–421

## 2. Root marker

Use `R/.architect-os-runtime-root`, containing exactly the ASCII bytes `architect-os-runtime-root/v1` followed by one LF. The **installer** places it once after independently identifying the intended mounted volume and selecting a dedicated directory. On CI, the job is the installer. There is no automatic `init` in the normal entry and no “mark if missing” recovery. Recreating a missing mount path and blessing it would reproduce the incident the marker is meant to prevent. Design, lines 918, 950 and 963–964

Admission requires an absolute canonical root, a directory, and exact equality with its physical path, including ancestors. Reject `/`, symlink components and ambiguous spellings. Open the marker without following a final symlink; check the opened descriptor refers to a regular file on the root device with the exact expected size and bytes. Reject pipes, devices, directories, wrong versions and trailing data. Validate existing `run`, `cache`, and their used descendants as physical directories on the admitted filesystem before opening anything for writing. Create missing children one component at a time **under the verified root only**. Record root device and inode. A subsequent destructive operation must independently recheck identity when that operation is introduced. Design, lines 938 and 948–955 · existing sandbox directory validation, lines 385–408

The marker answers an **accidental substitution**: a missing mount with no directory, an ordinary unmarked directory at its old name, or a symlink. It is public data. Someone who can copy the marker and substitute a directory, race an unmount, or run arbitrary code as the host user can defeat it. A device/inode sample identifies what was admitted at that instant. It supplies neither persistent hardware identity nor a quota. Hosted jobs may legitimately put home and root on the same device. Design, lines 944, 950, 964–965 and 971
