### Review findings

**R1 / departure 8.** `aos:78` sets `XDG_CONFIG_HOME=$dir/config`. Delivery then builds `host` from `deps.env` and passes it to both `GitRepository` and `GhForge`. Its allowlist explicitly includes `XDG_CONFIG_HOME`. An optional invocation of `./aos -- npm run deliver` already exercises that path. Commit 2 makes the launcher compulsory, but the regression begins in commit 1. aos:78 · delivery composition:81 · delivery allowlist:22 · brief:135

Capture presence and value **before** rebinding, overwriting any inherited copy of the launcher’s internal handoff. Use that capture only when constructing the allowlisted git/gh environment for an admitted delivery. Preserve an empty value as empty and an absent value as absent. Direct delivery must retain its current behavior. The ordinary command and nested gate keep the run’s XDG configuration. Add a witness through the real launcher and delivery composition with a scripted forge whose fixture identity is discoverable only through a non-default host config. Assert the exact forwarded names, cover the unset case, and verify that no host config or credential was copied into the run. A probe that merely echoes the variable would miss the regression. brief:80 · existing launcher probe:78

**R3.** The caught-error path writes the diagnostic at `main.ts:47` and returns 3. The shell’s `*) fail ;;` prints it again. Add `3) exit 3 ;;` and retain `fail` for an unclassified bootstrap failure or malformed success output. Add a shell-level assertion for the *caught-error* path requiring exactly one diagnostic, empty stdout, exit 3 and no dispatch. Keep the missing-module case separately. It fails before `runAdmission` starts and its current assertion checks only the stderr suffix. main.ts:47 · aos:53 · runtime-entry.feature:64

**R4 / departure 2.** `allocateRun` returns only a string. Both `if (!made)` and the failed receipt write return directly. Change the port to return an allocation carrying the new directory’s identity. Cover every failure after allocation, including an exception while making the receipt. Recheck the root, run parent and private run before rollback. Remove only material this attempt created, without following links. On an identity mismatch, leave the replacement alone and refuse dispatch. The existing witness checks that `rkept01` survives. It must also check that an unchanged partial run disappears and that a substituted run survives. Step 3 still owns successful-run retirement, dead-owner recovery and sweeping. None of those is needed to unwind the current call. ports.ts:33 · admit.ts:76 · admit.feature:265 · brief:193

**R5 / departure 5.** `aos:67` unsets four uppercase identifiers, and lines 74–77 assign four lowercase ones. The installed npm loader matches `npm_config_` case-insensitively, normalizes internal underscores to dashes, lowercases the key and assigns each matching value. Two spellings can therefore compete for one setting. Match using npm’s normalization, remove the **original names** for `cache`, `logs-dir`, `userconfig` and `globalconfig`, then supply exactly one canonical value each. The reviewer’s `/usr/bin/env -u` proposal is suitable for removing an identified name. Do not discover names by splitting `env` output on newlines or by evaluating shell text. Preserve unrelated variables, argv boundaries and final exec semantics. Witness both the child environment and npm’s effective settings with conflicting mixed-case and dashed inputs on the supported shells. aos:64 · installed npm loader:343 · current uppercase-only fixture:232

### Additional blockers found in the source

1. **The bootstrap executes a Node selected through the caller’s `PATH`.** `node=$(command -v node)` happens before `/usr/bin/env -i`. An absolute result says where lookup landed. The version check asks that same executable to identify itself. The later clean `PATH` cannot change the selection, and the fixture already demonstrates that a caller-supplied directory wins. Resolve the bootstrap interpreter from an installer- or runner-controlled trusted location, independently of the payload’s `PATH`, and use that executable for both the version check and admission. Preserve the caller’s command lookup after admission. Add a witness that a caller-path Node is never entered during bootstrap. aos:39 · launcher fixture:213 · brief:61
2. **Shared-directory setup writes before it has validated all existing destinations, and can refuse a legitimate concurrent admission.** `SHARED_DIRECTORIES` puts `run` before `cache`. On a marked root with no `run` and an unsafe existing `cache`, the code creates `run` before discovering the unsafe child. The scenario asserts only “no memory runtime run was allocated.” Separately, two admissions can both observe a missing component. The second `mkdirSync` can receive `EEXIST`, which the blanket catch maps to `failed`. First validate all existing shared components without writing. In the creation pass, handle `EEXIST` by re-inspecting the component and requiring a physical directory on the admitted device. Assert zero new paths for the unsafe-existing-child case and exercise overlapping first admissions for D11. root.ts:25 · Node adapter:109 · admit.feature:251 · brief:176
3. **The root observation can be attributed to the wrong device.** `sample()` obtains available space and device identity in separate calls. Admission never compares `rootSample.device` with the inspected root device. The receipt then uses `{ ...rootObservation, device: state.device, inode: state.inode }`, overwriting the observed device. Refuse before the first write if the sampled identity disagrees with the admitted root. Bind the space reading to a consistent root identity and add a port-level disagreement case. This addresses a detectable mismatch within the stated accidental-substitution model. Node adapter:95 · admit.ts:61 · admit.ts:87
4. **The marker reader can return the wrong exit class or accept an incomplete read as the whole marker.** Open failures are classified, but `fstatSync` and `readSync` errors escape to exit 3. The port and refusal table explicitly classify an unreadable marker as `RUNTIME_MARKER_INVALID`, exit 2. The code also parses the result of one `readSync` without establishing that it read the entire file. Read the bounded descriptor through EOF, reject an oversized or incomplete marker, close it on every path, and map marker inspection/read failures to `unreadable`. Cover a short read and an I/O error after open. Node adapter:65 · ports.ts:13 · brief:204
5. **npm can restore a startup override after the shell removes it.** The installed npm implementation assigns `env.NODE_OPTIONS = cliConf['node-options']` for lifecycle children. `aos` removes direct `NODE_OPTIONS` but leaves inherited npm `node-options` settings. Include that normalized key in the R5 sanitization and witness the environment inside an npm lifecycle child. The current direct probe and spy npm cannot establish that property. aos:67 · installed npm set-envs.js:102 · runtime-entry.feature:78
6. **The launcher never sets the specified private umask.** Explicit `0700` and `0600` modes protect the adapter’s own creations. At `exec "$@"`, the command still inherits the caller’s umask for subsequent writes. Set `umask 077` before setup and dispatch, and witness the mode of a file created by an admitted child launched from a permissive caller. brief:119 · Node adapter:30 · aos:86
7. **The memory adapter can overwrite an existing run.** It generates `r000001`, checks the parent and `makeable`, and then calls `Map.set`. `makeable` checks only injected failures and sealed parents. A pre-existing directory with the generated name loses its identity in memory, contradicting the exclusive-allocation port and undermining the R4 rollback witness. Skip occupied names and add a contract case that seeds an occupied name and verifies its identity and contents survive. memory adapter:129 · memory adapter:166 · ports.ts:33
