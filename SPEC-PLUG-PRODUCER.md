# Connect the Spec producer to architect-os

The named producer checkout was at `cda82f896517bf70e8a355cde876b9a65428093a`. Its bundled `mcp-server/index.js` had SHA-256 `d05fe8d1aa17de978107f6d6748b85174ecc9cd83d86c3c3d6e16ab241d22b22`. An offline MCP stdio probe of that bundle listed `full`, `summary`, `grounding`, `validation`, and `action` for `get_pipeline_state`. Both versioned planning reads returned input-validation error `-32602` before checkpoint lookup. The older packaged-producer receipts in [Define](docs/define.md) and [Plan](docs/plan.md) refer to other revisions.

The consumer pins and stages the producer as [Define](docs/define.md) describes. The operator's digest covers `mcp-server/**` (without `mcp-server/node_modules/.bin`) and `packages/skill/**`: the SHA-256 of the `shasum -a 256` listing of those files sorted by the bytes of their paths. The command lines are `define <run_id> <root> <producer-sha256>` and `plan:proposal <run_id> <root> <producer-sha256> <step> <define-file>`, and the planning configuration's field is `producer_sha256`. Any other link, a special file, a name with a newline or a backslash, a missing `mcp-server/index.js` or `packages/skill/skill-config.json`, or a tree over 20 000 files or 256 MiB is refused (`SPEC_PRODUCER_LINK`, `_FILE`, `_PATH`, `_INCOMPLETE`, `_TOO_LARGE`), a different digest with `SPEC_PRODUCER_MISMATCH`, all before anything starts. The host then runs a private copy of those bytes, never the plugin root, under Node's permission model. So the shipped server must: work when started directly from a copy that keeps the layout `mcp-server/` + `packages/skill/` (it finds its plugin root through `packages/skill`); read nothing at run time outside that copy except its data directory `~/.prd-gen` (the planning host gives it a private home and temporary directory instead), and the skill configuration named by `PRD_GEN_SKILL_CONFIG`, which points into the copy; start no child process, worker or network connection, and load no native addon, for the two projections (the host refuses addons, so `better-sqlite3` is not loaded and the server must answer without its sqlite caches); and hold no link outside `node_modules/.bin`. Its runtime dependencies must already be provisioned; a read never runs `bin/ensure-deps.mjs`.

The producer host calls `start_pipeline`, executes each returned action and advances by `submit_action_result`. It can recover the pending action with `get_pipeline_state(format: "action")`. At the export stage the host acknowledges the writes of `01-prd.md` and `07-jira-tickets.md`. The implementation gate also handles `10-verification-report.md` and waits for a human decision. Keep the `run_id` from the pipeline and the persisted checkpoint. The Markdown deliverables are for the operator and the versioned reads come from the checkpoint.
