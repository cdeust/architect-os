# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Fixed

- The cause of the failed Claude security review is removed; its first run on GitHub will show whether it starts. Under `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB`, Claude Code does not start on Linux without bubblewrap, and `anthropics/claude-code-action` installs it only for `allowed_non_write_users`: the review failed on `ubuntu-24.04` (run 45771449067), while `claude-review.yml` and `claude.yml` passed on what `ubuntu-latest` gave that day. In the three workflows a step `bubblewrap` now installs `bubblewrap` and `socat`, allows user namespaces and creates one, on `ubuntu-24.04`, and the action runs only when the outcome of that step, and of the step that installs the managed settings, is success. The step makes a review start and stops a runner without a working bubblewrap before the model is called; keeping credentials from subprocesses remains Claude Code's. No job of any workflow names a `-latest` image (`docs/infrastructure.md`, "Bubblewrap before the scrub").
- Known and not fixed here, an open defect of `main`: `pull_request`, `pull_request_review` and `pull_request_review_comment` run the workflow file of the pull request's merge commit, so an account with write access can open a pull request whose `claude-review.yml`, `claude-security-review.yml` or `claude.yml` gives `CLAUDE_CODE_OAUTH_TOKEN` to a step it wrote; every guard of these files holds for the committed file only. The correction is the local branch `claude-secrets-environment` (`docs/infrastructure.md`, "Which commit a run takes its files from").

### Changed

- `claude-review.yml` and `scripts/ci_review_budget.py` were taken from Cortex (Cortex #980), and `claude-review.yml` has changed since (the entries of this file that name it): the review workflow authorizes the pinned action's fetch only on a private repository and names no reviewer count, and the budget script counts only reviews run under the review contract (ADR-1129) and refuses a `GITHUB_OUTPUT` outside `RUNNER_TEMP`. `test_ci_review_budget.py` is Cortex's test.
- A merge that waits no longer fails `Pipeline after merge` (Cortex ADR-1128). Each head wakes the resolver twice, once at the end of the Pipeline and once at the end of the review, and the first wake-up is held; it exited 1, so the default branch showed a failed run for every normal merge. A held merge, or a head that advanced, now ends green with a notice and writes no output, and `close-issues` requires a pull request number. Every other refusal still fails.
- The review prompt puts the run's link just before the verdict line in every comment that carries it (Cortex ADR-1130). The resolver reads a verdict only from a comment that links the review run of the head; a review posted with `gh pr comment` can carry the verdict without the link, and an approved, green pull request then stays unmerged.
- The Claude review and the merge follow Cortex's CI (`cdeust/Cortex`): `claude-review.yml` replaces `claude-code-review.yml` (three reviews per pull request at most, a verdict line), `scripts/ci_review_budget.py` counts them, and `pipeline-after-merge.yml` merges into `main` a pull request whose gate succeeded and whose review approves.
- The repository was renamed from `agentic-ai` to `architect-os` (npm scope `@agentic-ai/*` is now `@architect-os/*`); GitHub redirects the old URL.
- The repository was replaced by the architecture skeleton. The previous content is archived under the tag `archive/v1-2026-10-29` and is no longer maintained.

### Added

- `claude-review.yml` runs the official mode of `anthropics/claude-code-action` v1.0.290 (`examples/pr-review-comprehensive.yml`), the pin of the three workflows that use the action. It publishes only through the action's comment tools, with no shell: `Bash(gh pr comment:*)` could publish any file of the runner with `--body-file`, and the action's token sat in `.git/config` up to v1.0.271. A trusted step installs managed settings in `/etc/claude-code`, which deny the shell, the web, writes, reads of `.git` and outside the checkout, and the bypass and auto modes. They also install a `PreToolUse` hook, `.github/claude-review/comment-guard.py`, which refuses a comment holding a mention, a misplaced verdict or a credential before it is posted. The diff is written by a trusted step. The verdict is the last line of the tracking comment, after the link of the run. `features/integration/review-restriction.feature` shows both reviews' settings refusing, before a real Claude Code and a scripted model, what an injected prompt asks. The publisher of the security review reads a credential after removing the characters that render as nothing. No workflow that runs the action leaves its permission mode to it: `claude.yml` sets `acceptEdits` and the reviews `default`, and each installs managed settings that forbid the auto and bypass modes; a scenario fails if one could run in auto mode.
- `claude-security-review.yml`: an advisory security review of each trusted pull request by Claude, once, on the owner's subscription, with `anthropics/claude-code-action` at the pin of `claude-review.yml`. The reviewer returns JSON and posts nothing; a job without a model or a secret checks it against its schema (no non-finite number, no reason that echoes the answer), writes each field as one code span on one line (no link, image, HTML, entity, @mention nor `Verdict:` line renders), refuses the shape of a credential, and posts one comment. It blocks no merge. The audit and its filter are adapted from `anthropics/claude-code-security-review` (`.github/claude-security-review/`). Managed settings restrict Claude Code to reading the checkout of `main`. `features/descriptive/security-review.feature` holds its guards, each with a broken copy refused. `docs/infrastructure.md` says why the action of Anthropic is not the engine.
- Four-tier skeleton: `proxy`, `gateway`, `services/memory` (with `worker`), `data`, and `packages/contracts`.
- `Result<T>` contract, run registry and typed data operations, SQL migrations 0001 (runs) and 0002 (memory with pgvector).
- Architecture guard (`npm run arch`) and its proof test; end-to-end test through the gateway with in-memory adapters.
- `compose.yaml` with four network zones; worker and service Dockerfiles.
- `CLAUDE.md`, `.claude/settings.json`, review subagents, `/review-pr`, and documentation under `docs/`.
- GitHub workflows: `ci.yml`, and `claude.yml` / `claude-code-review.yml` from `anthropics/claude-code-action`.
- Behaviour expressed in descriptive files (docs/design.md, ADR 12): data operations as `data/sql/*.sql` with the table `data/sql/operations.json` and one generic executor; migration 0003 makes a completed run immutable in the database; worker system prompts as `services/memory/worker/prompts/<tool>.md`; internal tools declared once in `INTERNAL_TOOLS`; gateway routes derived from the tool owners. Each descriptive file is checked by a load-and-schema test.
